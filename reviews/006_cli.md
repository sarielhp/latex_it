[SEVERITY]: Major
[LOCATION]: `latex_it`, `LatexCLI.add_compilation_options_primary` (the `--lua`, `--xe`, `--pdflatex` blocks) and `LatexCLI.normalize_argv!`
[ROOT CAUSE]: The mandate requires exactly one canonical, documented form per option and forbids advertising aliases in help text. Engine selection already has a canonical form, `--engine ENGINE`, but `--lua`, `--xe`, and `--pdflatex` are registered as separate, fully-documented options whose help text literally says "Shortcut for --engine=…". This is alias bloat that `-h` explicitly advertises, rather than the hidden-legacy-alias pattern the codebase correctly uses elsewhere (e.g. `normalize_argv!` silently rewrites `-pdflatex`/`-xelatex`/`-lualatex` to their `--` forms without any `opts.on` entry).
[FAILURE TRACE]: Run `l -h` and observe four different documented ways to pick an engine (`--engine ENGINE`, `--lua`, `--xe`, `--pdflatex`), each with its own help line. A new user has no way to tell which is "the" interface, and scripts/docs will inconsistently pick different spellings for the same operation, which is exactly the alias-proliferation the CLI lens exists to prevent.
[REMEDIATION]: Fold the shortcuts into `normalize_argv!` (hidden translation) and delete their `opts.on` entries so only `--engine ENGINE` is documented:
```ruby
def self.normalize_argv!(argv)
  argv.map! do |arg|
    case arg
    when '--lua' then '--engine=lualatex'
    when '--xe' then '--engine=xelatex'
    when '--pdflatex' then '--engine=pdflatex'
    # ...existing legacy single-dash cases...
    else arg
    end
  end
end
```
and remove the three corresponding `opts.on('--lua'...)`, `opts.on('--xe'...)`, `opts.on('--pdflatex'...)` blocks from `add_compilation_options_primary`.

[SEVERITY]: Moderate
[LOCATION]: `latex_it`, `LatexCLI.build_option_parser` / `add_compilation_options_primary` / `add_compilation_options_secondary` / `add_arxiv_options` / `add_general_options`
[ROOT CAUSE]: The mandate caps `-h` output at "strictly <= 20 lines". Counting the actual `opts.on` registrations (10 in `add_compilation_options_primary` + 22 in `add_compilation_options_secondary` + 6 in `add_arxiv_options` + 3 in `add_general_options` = 41 option lines) plus the banner and four section separators, `l -h` prints roughly 48 lines — more than double the mandated ceiling.
[FAILURE TRACE]: Run `l -h | wc -l`; the output is ~48 lines, immediately exceeding the 20-line budget the lens mandates for short help.
[REMEDIATION]: Split help into a genuinely short `-h` (most common ~10-12 flags) and push the remainder behind `-E`/`--help-all`, e.g.:
```ruby
opts.on('-h', '--help', 'Show condensed help (see -E for full option list)') do
  puts condensed_help_lines(opts) # curated subset, <=20 lines
  exit 0
end
```
with the full `OptionParser` summary reserved for a separate `--help-all`/`-E` invocation.

[SEVERITY]: Major
[LOCATION]: `lib/latex_it/diagnostics.rb`, `LaTeXDiagnostics#report_errors` and `#print_diagnostics_body` / `#render_diagnostic_entry`
[ROOT CAUSE]: The lens requires clean stdout/stderr separation with actionable error reporting. `report_errors` — the tool's entire compile-failure report (banner, per-file diagnostics, "See … for full error details", summary line) — is emitted exclusively via `puts` (stdout), then calls `exit 1`. Meanwhile unrelated lower-level failures (`warn "Bibliography tool unavailable…"`, `warn "[FAIL] …"` in arxiv.rb/packager.rb) correctly go to stderr. The result is an inconsistent split where the tool's primary, most important error output — the one correlated with the non-zero exit code — lives on stdout instead of stderr.
[FAILURE TRACE]: Introduce a syntax error into `paper.tex` and run `l paper.tex 2>err.log; echo $?; cat err.log`. The exit code is `1`, but `err.log` is empty — every line of the actual error report (the red banner, the `l.N` snippet, the "Hint:" line, and the final error/alert/warning summary) was written to stdout, so any script or CI job that captures stderr to detect/log failures (the standard Unix idiom) sees nothing.
[REMEDIATION]: Route the failure-path output through stderr while preserving normal build progress on stdout:
```ruby
def report_errors(loga)
  raw = LaTeXUtils.safe_read(loga)
  content = LaTeXUtils.filter_subcommand_noise(raw)
  err_out = $stderr
  err_out.puts Rainbow("\n===============...").red.bright
  err_out.puts Rainbow(' ERROR: LaTeX Compilation Failed!').red.bright
  # ... write the diagnostics body to err_out instead of $stdout ...
  exit 1
end
```
(threading an explicit `io:` target through `print_diagnostics_body`/`render_diagnostic_entry` rather than hardcoding `puts`).

[SEVERITY]: Moderate
[LOCATION]: `latex_it`, `LatexCLI.add_compilation_options_primary` (`--pdf` and `--fast` entries)
[ROOT CAUSE]: `--pdf` is registered with the description "Generate PDF output (default behavior)" but its block body is empty (`# No-op`) — it does nothing and no alternative output mode exists, so its presence in `-h` implies a choice that isn't real. `--fast` similarly is a compatibility no-op ("incremental rebuilds are automatic") but is kept as a fully documented, visible option rather than a hidden legacy alias per Rule 2's guidance. Both inflate the already-oversized help output with entries that mislead users into thinking they control something.
[FAILURE TRACE]: A user reading `l -h`, trying to produce a DVI or PS artifact, tries `--pdf` variations or searches for a "non-PDF" counterpart that does not exist; `--fast` similarly invites the (false) belief that omitting it disables incremental builds.
[REMEDIATION]: Remove `--pdf` entirely (it documents a non-choice), and demote `--fast` to a silently-accepted, hidden legacy flag like the other compatibility shims in `normalize_argv!`:
```ruby
def self.normalize_argv!(argv)
  argv.reject! { |a| a == '--fast' } # accepted-but-no-op; not documented
  argv.map! { |arg| ... }
end
```
removing both corresponding `opts.on` blocks from `add_compilation_options_primary`.
